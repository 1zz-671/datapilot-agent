# DataPilot MVP 需求与验收说明

- 版本：v0.1
- 状态：需求草案
- 负责人：李孜政
- 更新时间：2026-10-03

## 1. 项目目标

DataPilot 是面向企业经营分析与数据开发的智能数据助手。

第一版聚焦电商经营分析：用户用自然语言提出数据问题，
系统识别指标、时间范围和分组条件，执行安全的只读查询，
返回数据结果、指标口径及实际执行的 SQL。

第一版的核心目标是：
让一个常见经营分析问题从输入到结果形成可验证的完整闭环。

## 2. 目标用户与业务场景

### 目标用户

电商运营分析人员，以及负责支持运营需求的数据分析人员。

### 当前工作方式

运营人员提出问题 → 数据人员确认统计口径 →
编写 SQL → 执行查询 → 整理并解释结果。

常见问题：
- 简单查询也需要等待数据人员处理。
- 相同指标可能采用不同口径。
- 查询结果缺少 SQL 和口径说明，难以核对。

### 第一版使用场景

运营人员输入：

“查询 2026 年 9 月各地区的支付销售额。”

系统返回：
- 各地区支付销售额的数据表。
- 实际使用的时间范围。
- 支付销售额的统计口径。
- 实际执行的 SQL。
- 数据更新时间与请求编号。

## 3. MVP 范围

### 必须实现

1. 一个 PostgreSQL 演示数据库。
2. 使用模拟数据，不包含真实客户信息。
3. 支持支付销售额、支付订单量和客单价三个指标。
4. 支持按日期、收货地区和商品类别分组。
5. 支持明确的日期范围、自然月和“上个月”。
6. 支持汇总、分组、排序和 Top N 查询。
7. 提供一个接收自然语言问题的分析接口。
8. 返回数据结果、指标口径、时间范围和执行 SQL。
9. 对 SQL 进行安全校验，并使用只读数据库账号。
10. 限制查询时间和返回行数。
11. 对无数据、不支持的问题和执行错误给出明确说明。

### 第一版暂不实现

- 利润、退款净额和预测分析。
- 任意数据库和任意业务表的自动接入。
- 多租户、完整角色权限系统。
- ETL 写入和自动修改业务数据。
- 完整 React/Vue 前端。
- PDF 报告、复杂图表和异步任务系统。

第一版通过 FastAPI 的接口文档完成交互验证。

## 4. 数据范围与业务约定

### 演示数据

- 数据期间：2026 年 7 月至 9 月。
- 数据内容：客户、商品、订单和订单明细。
- 金额单位：人民币元。
- 金额计算使用精确小数类型。
- 业务时区：Asia/Shanghai。
- 数据生成规则与随机种子固定，便于复现。

模拟数据应包含：
- 已支付和未支付订单。
- 一个订单包含多个商品的情况。
- 多个地区和多个商品类别。
- 月初、月末等时间边界记录。
- 没有订单的日期或查询范围。

### 时间约定

经营指标按支付时间统计。

时间范围使用“包含开始时间，不包含结束时间”的规则。

例如 2026 年 9 月：
2026-09-01 00:00:00 ≤ 支付时间 < 2026-10-01 00:00:00。

“上个月”根据请求当天及业务时区计算，
并在响应中展示实际起止时间。

### 历史维度约定

地区使用下单时保存的收货地区快照。

商品类别使用下单时保存的商品类别快照，
避免客户或商品资料后续变化影响历史统计。

## 5. 指标口径

### 支付销售额

- 含义：指定范围内成功支付订单的实付金额总和。
- 时间字段：订单支付时间。
- 过滤条件：支付成功。
- 暂不扣除后续退款。
- 无匹配订单时返回 0。

按地区统计时使用订单实付金额。

按商品类别统计时使用订单明细分摊后的实付金额；
同一订单的明细实付金额合计必须等于订单实付金额。

不得在关联订单明细后重复累加订单金额。

### 支付订单量

- 含义：指定范围内成功支付订单的数量。
- 时间字段：订单支付时间。
- 订单按订单编号去重。
- 无匹配订单时返回 0。

按商品类别统计时，一个订单在每个包含的类别内计数一次。
因此各类别订单量之和可能大于总订单量。

### 客单价

- 公式：支付销售额 ÷ 支付订单量。
- 分子与分母必须使用相同时间范围和过滤条件。
- 支付订单量为 0 时返回 null，并说明没有支付订单。
- 展示时保留两位小数。

## 6. 代表问题与预期行为

| 编号 | 用户问题 | 预期行为 |
|---|---|---|
| Q01 | 2026 年 9 月支付销售额是多少？ | 返回月度支付销售额 |
| Q02 | 2026 年 9 月支付订单量是多少？ | 返回月度支付订单量 |
| Q03 | 2026 年 9 月客单价是多少？ | 返回月度客单价 |
| Q04 | 2026 年 9 月各地区支付销售额是多少？ | 按收货地区分组 |
| Q05 | 2026 年 9 月各商品类别支付销售额是多少？ | 按类别统计明细实付金额 |
| Q06 | 2026 年 9 月每天的支付销售额是多少？ | 按业务时区的日期分组 |
| Q07 | 2026 年 9 月销售额最高的 5 个地区有哪些？ | 按销售额降序返回前 5 名 |
| Q08 | 2026 年 9 月福建地区的客单价是多少？ | 增加地区过滤条件 |
| Q09 | 上个月支付销售额是多少？ | 解析为明确日期范围并返回结果 |
| Q10 | 2026 年 9 月利润是多少？ | 返回指标暂未支持，不生成 SQL |

数据库建立后，为每个支持的问题补充人工参考 SQL 和预期结果，
作为后续规则模板与大模型生成查询的验证依据。

## 7. 查询流程与结果要求

### 第一版查询流程

问题输入 → 识别指标与条件 → 检查支持范围 →
规则模板生成 SQL → 安全校验 → 只读执行 → 返回结果。

先完成规则模板闭环，再接入大模型生成 SQL。
大模型接入后仍须遵守相同的指标口径与安全要求。

### 成功响应必须包含

- request_id：请求编号。
- status：执行状态。
- metric：指标名称及口径版本。
- time_range：实际统计时间范围与时区。
- data：查询结果。
- sql：实际执行的 SQL。
- data_updated_at：演示数据集最近更新或导入时间。
- truncated：结果是否被截断。
- warnings：需要用户注意的结果限制。

数据更新时间不得使用本次查询时间代替。

## 8. 异常与安全要求

### 问题处理

- 指标不支持：明确说明支持范围。
- 缺少必要时间条件：提示用户补充时间范围。
- 业务含义存在歧义：提示用户澄清。
- 无匹配数据：说明无数据，不生成虚构结论。
- 汇总查询无订单：按指标约定返回 0 或 null。

### SQL 执行

- 仅允许经过校验的单条只读查询。
- 拒绝写入、DDL、多语句及非授权表字段访问。
- 不允许调用未经批准的数据库函数。
- 使用只读账号，仅授予演示数据表的查询权限。
- 数据库查询超时默认 10 秒。
- 返回行数默认最多 200 行。
- 超出行数时必须标记结果被截断。
- SQL 校验通过不代表结果正确，仍需与参考结果核对。

### 日志

记录请求编号、执行状态、耗时和错误类型，
便于追踪一次查询的处理过程。

日志不得记录数据库密码或 API 密钥。

## 9. 验收标准

### 功能正确性

- Q01 至 Q08 的结果与人工参考 SQL 一致。
- Q09 能根据固定的测试日期正确解析“上个月”。
- Q10 返回指标不支持的说明。
- 月份边界和业务时区处理正确。
- 未支付订单不参与支付指标计算。
- 关联明细不会造成订单金额重复计算。
- 零订单时的客单价返回 null。
- 每次成功响应都展示 SQL、口径和实际时间范围。

### 安全与异常

- 写入、DDL、多语句和非授权表访问被拒绝。
- 数据库账号不能修改演示业务数据。
- 超时查询被终止，并返回明确错误。
- 结果截断有明显标记。
- 无数据时不生成虚构分析。
- 请求编号能对应到执行日志。

### 可复现性

- 新环境能按 README 安装依赖并启动。
- 数据建表与生成过程可重复执行。
- 必要配置有示例和字段说明。
- 参考 SQL 与验证方法保存在仓库中。
